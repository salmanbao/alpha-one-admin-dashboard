  8029→### Pattern precedent: key-remount + lazy useState for Sheet drawers
  8030→
  8031→This task established a cleaner pattern than the `localState || propValue` fallback used in `marketing-ad-spend-page.tsx` / `marketing-email-campaigns-page.tsx`. By passing a `key` prop to the Sheet component (changing when the target changes), the entire Sheet remounts, and all `useState` calls re-initialize from props via lazy initializers. This:
  8032→1. Avoids the `react-hooks/set-state-in-effect` ESLint error (introduced by React 19 / Next.js 16's stricter rule).
  8033→2. Allows the user to clear form fields normally (unlike the `localState || propValue` pattern which prevents clearing back to empty).
  8034→3. Has no observable UX regression — Sheet close/open animations still work; the key changes only happen on user-initiated transitions (open new coupon / open new link).
  8035→
  8036→Future Sheet drawer implementations should prefer this pattern over `useEffect` prefill or `localState || propValue` fallback.
